# `devtools/`

> أدوات التطوير — **بيئة التطوير وحدها**

| | |
|---|---|
| **الطبقة** | فوق الجميع |
| **يعتمد على** | كل النطاقات |
| **يعتمد عليه** | لا شيء — ولا يجوز |

## لماذا تطبيق منفصل؟

بذرة البيانات تلمس **كل** نطاق: الكتالوج والمخزون والتسعير والطلاب
والطلبات. وضعها داخل أي نطاق يجعله يستورد نطاقات لا علاقة له بها،
فيلوّث مخطط التبعيات الذي يقرأه المطوّر ويثق به.

هنا يستورد الجميع، ولا يستورده أحد — يفرضه `import-linter`.

## ⚠️ غير مثبّت في الإنتاج

`devtools` مُضاف إلى `INSTALLED_APPS` في **`config/settings/dev.py` وحده**.

هذا ليس تنظيمًا — إنه **الضمانة الأمنية**. البذرة تُنشئ حسابات
بكلمة مرور معروفة ومنشورة في الوثائق. فحص `if settings.DEBUG` داخل
الأمر يمكن تجاوزه بمتغيّر بيئة خاطئ؛ أما أمر **غير موجود** فلا
يُشغَّل بأي حال:

```console
$ DJANGO_SETTINGS_MODULE=config.settings.prod python manage.py seed_dev
Unknown command: 'seed_dev'
```

## الأوامر

| الأمر | الفعل |
|---|---|
| `seed_dev` | بذرة كاملة قابلة للتشغيل مرارًا |
| `seed_dev --reset` | حذف بيانات البذرة ثم إعادة إنشائها |
| `seed_dev --minimal` | الإعدادات والبنية فقط — بلا منتجات ولا مستخدمين |
