# استراتيجية المعرّفات

[← العودة للفهرس](../README.md)

> **قاعدة ملزمة: لا يظهر أي معرّف تسلسلي في أي URL أو استجابة API. إطلاقًا.**

---

# ١. لماذا

| الخطر | المثال |
|---|---|
| **التعداد (Enumeration)** | `/orders/1` … `/orders/9999` — كشف كل الطلبات بحلقة بسيطة |
| **تسريب معلومات تجارية** | منافس يطلب طلبًا اليوم وآخر بعد شهر ⟵ يعرف حجم مبيعاتك الشهري بالطرح |
| **تسريب حجم النشاط** | `users/1247` يخبر الجميع أن لديك ١٢٤٧ مستخدمًا |
| **الربط عبر الأنظمة** | نفس الرقم في الفاتورة والرابط وسجل الشحن ⟵ تجميع بيانات |
| **الروابط المخمَّنة** | ملف مرفوع باسم `01.jpg` يُخمَّن بلا أي صلاحية |

هذا ليس تفصيلًا تجميليًا — **الرقم التسلسلي يفصح عن معلومة تجارية بمجرد وجوده.**

# ٢. ⚠️ التحذير الأهم: UUID ليس تفويضًا

> **إخفاء المعرّف تعتيم، وليس تحكمًا بالوصول.**

الـ UUID يجعل التخمين مستحيلًا. لكنه **لا يحمي** إذا تسرّب المعرّف — والمعرّفات تتسرّب:

سجلات الخادم · تاريخ المتصفح · ترويسة `Referer` · روابط مُشارَكة · لقطات شاشة · أدوات المطوّر · وسطاء الشبكة.

```python
# ❌ خطأ شائع قاتل — "المعرّف UUID فهو آمن"
class OrderDetailAPI(RetrieveAPIView):
    queryset = Order.objects.all()  # أي مستخدم يقرأ أي طلب


# ✅ الصحيح — UUID + فحص ملكية
class OrderDetailAPI(RetrieveAPIView):
    def get_queryset(self):
        return Order.objects.filter(customer=self.request.user.customer)
```

**الثغرة الحالية في `orders/api.py:24,40,47,72,112,136` تبقى ثغرة حتى بعد تحويلها إلى UUID.**

> **UUID + فحص ملكية = أمان.**
> **UUID وحده = تأخير للمهاجم فقط.**

# ٣. تصنيف المعرّفات

**ليست كل الكيانات تُعامل بنفس الطريقة.** ثلاثة أنواع:

| النوع | الاستخدام | الأمثلة |
|---|---|---|
| **Slug** | محتوى عام يحتاج SEO | منتج · فئة · براند · مقال |
| **UUIDv7** | كل ما هو خاص أو مملوك | طلب · سلة · عميل · موظف · مصروف · وردية · دفعة · شحنة |
| **رقم عمل** | ما يحتاج البشر نطقه | رقم الطلب · رقم الفاتورة · رقم الإيصال |

## Slug للكتالوج — وليس UUID

```text
✅ /store/p/stethoscope-littmann-classic-iii
❌ /store/p/018f4e2a-9c3b-7d1e-a5f0-2b8c4d6e1a90
```

**السبب:** صفحة المنتج تحتاج SEO. رابط UUID كارثة على محركات البحث وعلى ثقة المستخدم.

**وهذا آمن** لأن الكتالوج **عام أصلًا** — لا سر في وجود منتج. والمنتجات المقيّدة يحميها `access/` لا إخفاء الرابط.

| الكيان | المعرّف في الرابط |
|---|---|
| منتج · فئة · براند · مصنّع | `slug` |
| جامعة · كلية | `slug` |
| كل ما عداه | `UUIDv7` |

> ⚠️ الـ slug يجب أن يكون **فريدًا وثابتًا**. تغييره يكسر الروابط و SEO — احتفظ بالقديم كتحويل ٣٠١.
> الكود الحالي في `products/models.py:30-32` يعيد توليد الـ slug **في كل حفظ** — يجب إصلاحه.

# ٤. UUIDv7 وليس v4

| | UUIDv4 | **UUIDv7** |
|---|---|---|
| التوليد | عشوائي بالكامل | بادئة زمنية + عشوائي |
| ترتيب الفهرس | ❌ عشوائي ⟵ انقسام صفحات B-tree · إدراج بطيء | ✅ تصاعدي ⟵ موضعية ممتازة |
| السرية | ✅ غير قابل للتخمين | ✅ غير قابل للتخمين |
| يكشف؟ | لا شيء | **وقت الإنشاء تقريبًا** |
| الأداء عند الملايين | يتدهور | مستقر |

**التوصية: UUIDv7.**

كشف وقت الإنشاء ليس مشكلة — الطلب يحمل `created_at` في استجابته أصلًا. أما تدهور الأداء مع UUIDv4 على جداول بملايين الصفوف فمشكلة حقيقية.

## التنفيذ

```python
# uuid_utils أو uuid6 من PyPI  (وuuid.uuid7 مضمّن في إصدارات Python الحديثة)
import uuid_utils


class UUIDPrimaryKeyModel(models.Model):
    id = models.UUIDField(
        primary_key=True,
        default=lambda: uuid.UUID(bytes=uuid_utils.uuid7().bytes),
        editable=False,
    )

    class Meta:
        abstract = True
```

يسكن في `core/models/` ويرثه كل نموذج مكشوف.

# ٥. أي جدول يأخذ UUID وأيها لا

> **القاعدة: كل نموذج يظهر في رابط أو استجابة API ⟵ UUIDv7. الجداول الداخلية عالية الحجم ⟵ BigInt.**

هذا يمنع الإفراط في الهندسة ويحفظ الأداء معًا.

| الجداول | المفتاح | السبب |
|---|---|---|
| `User` · `Customer` · `Employee` · `Order` · `Cart` · `Address` · `Shipment` · `Payment` · `Expense` · `POSSession` · `Batch` · `StockLocation` · `Coupon` | **UUIDv7** | تظهر في روابط أو استجابات |
| `Product` · `Category` · `Brand` | **UUIDv7** + `slug` فريد | UUID للـ API الداخلي · slug للرابط العام |
| `AuditLog` · `StockMovement` · `UserSession` · `NotificationLog` · `PaymentTransaction` | **BigInt** | داخلية · حجم ضخم · **لا تظهر في رابط أبدًا** |
| جداول الوصل (M2M) | **BigInt** | لا تُعرَّف خارجيًا |

**تنبيه:** جدول بمفتاح BigInt قد يحمل مفاتيح أجنبية من نوع UUID — وهذا سليم تمامًا.

## ⚠️ توقيت القرار

تغيير نوع المفتاح الأساسي بعد تراكم البيانات **أشد ألمًا من تغيير `AUTH_USER_MODEL`** — يمس كل مفتاح أجنبي في قاعدة البيانات.

**يُحسم في المرحلة ١، مع `AUTH_USER_MODEL` و`Decimal`.** البيانات الآن وهمية — التكلفة صفر.

# ٦. أرقام العمل — ما ينطقه البشر

الـ UUID غير صالح للاستخدام البشري. العميل لا يستطيع قراءة `018f4e2a-9c3b-...` على الهاتف.

```text
رقم الطلب:    ORD-2026-7K3M9P
رقم الفاتورة: INV-2026-4T8R2X
رقم الإيصال:  RCP-2026-9B5N1Q
كود العميل:   CUS-8F3K2M
```

| القاعدة | التفصيل |
|---|---|
| **غير تسلسلي** | جزء عشوائي — لا `ORD-000001` |
| **أبجدية Crockford Base32** | بلا `I` `L` `O` `U` — يمنع اللبس في النطق والكتابة |
| **عشوائية آمنة** | `secrets` لا `random` |
| **فريد** | قيد `unique` + إعادة توليد عند التصادم |
| **ليس معرّف الرابط** | الرابط يستخدم UUID · رقم العمل للعرض والبحث والدعم الفني |
| **طول كافٍ** | ٦-٨ محارف عشوائية ⟵ مساحة كبيرة تمنع التخمين |

# ٧. ⛔ الكود الحالي — مشكلتان مؤكدتان

## ١. مولّد الأكواد غير آمن تشفيريًا

`utils/generate_code.py`:

```python
import random  # ⛔ Mersenne Twister — قابل للتنبؤ


def generate_code(length=8):
    data = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ"
    code = "".join(random.choice(data) for x in range(length))
    return code
```

**أين يُستخدم:** `Profile.code` (كود **تفعيل الحساب**) و `Order.code`.

**الخطورة:** `random` مولّد شبه عشوائي قابل للتنبؤ. من يراقب عددًا كافيًا من المخرجات يستطيع استنتاج الحالة الداخلية وتوقّع الأكواد التالية — **وكود التفعيل يمنح الوصول إلى الحساب**.

**الإصلاح:**
```python
import secrets

ALPHABET = "0123456789ABCDEFGHJKMNPQRSTVWXYZ"  # Crockford — بلا I L O U


def generate_code(length=8):
    return "".join(secrets.choice(ALPHABET) for _ in range(length))
```

## ٢. ملفات الوسائط بأسماء تسلسلية

```
media/brand/01.jpg  02.jpg  03.jpg  …
```

قابلة للتعداد بالكامل. نفس تسريب المعرّف التسلسلي، بل أسوأ — بلا أي فحص صلاحية.

**الإصلاح:** أسماء عشوائية + مسارات مجزّأة:

```text
media/catalog/products/8f/3k/8f3k2m9p4t8r2x5n1q7w.webp
```

| نوع الملف | الحماية |
|---|---|
| صور المنتجات والبراندات | اسم عشوائي · عام |
| **وثائق التحقق · مستندات الموظفين · فواتير المصروفات · الإيصالات** | اسم عشوائي · **غير عام** · **رابط موقّع بصلاحية زمنية** · فحص تفويض عند كل تحميل |

# ٨. قواعد الـ API

| القاعدة | التفصيل |
|---|---|
| **المفتاح الداخلي لا يُكشف** | الجداول ذات BigInt لا تُصدّر `id` في أي استجابة |
| **حقل واحد للتعريف** | الـ serializer يُصدّر `id` (UUID) أو `slug` — **لا الاثنين ولا رقمًا داخليًا** |
| **العدّادات لا تُكشف** | ممنوع إرجاع `total_users: 1247` لغير المصرّح لهم |
| **رسائل الخطأ لا تكشف الوجود** | `404` لا `403` عند طلب مورد لا يملكه المستخدم — وإلا صار الفرق بين الردين أداة تعداد |
| **الترقيم بالمؤشر** | `cursor` لا `offset` على القوائم الحساسة — `offset` يكشف الحجم الكلي |

## نقطة دقيقة: `403` مقابل `404`

```text
GET /api/v1/orders/<uuid-موجود-لغيري>/     ⟵ 404
GET /api/v1/orders/<uuid-غير-موجود>/       ⟵ 404
```

**ردّان متطابقان.** لو أعاد الأول `403` والثاني `404`، لصار الفرق بينهما وسيلة لمعرفة أي المعرّفات موجودة.

# ٩. أثر ذلك على الفرونت إند

```text
✅ /store/p/stethoscope-littmann-classic-iii
✅ /account/orders/018f4e2a-9c3b-7d1e-a5f0-2b8c4d6e1a90
✅ /admin/catalog/products/018f4e2a-...
✅ /admin/accounts/users/018f4e2a-...

❌ /account/orders/1247
❌ /admin/products/89
```

| القاعدة | التفصيل |
|---|---|
| المسارات تستخدم `slug` للكتالوج و `UUID` لما عداه | — |
| **رقم العمل يُعرض ولا يُوجَّه به** | الشاشة تعرض `ORD-2026-7K3M9P` والرابط يحمل الـ UUID |
| البحث برقم العمل | `/account/orders?q=ORD-2026-7K3M9P` ⟵ يحوّل إلى صفحة الـ UUID |
| ممنوع في `localStorage` | لا تُخزَّن معرّفات موارد غير مملوكة للمستخدم |
| القوائم | تُرسَل UUIDs فقط — لا مفاتيح داخلية في حمولة الاستجابة |
