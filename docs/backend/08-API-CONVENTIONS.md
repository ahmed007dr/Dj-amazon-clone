# ١. البنية العامة

```text
https://api.example.com/api/v1/<domain>/<resource>/
```

| القاعدة | التفصيل |
|---|---|
| **الإصدار في المسار** | `/api/v1/` — لا في الترويسة |
| **الشرطة المائلة الختامية** | إلزامية (اصطلاح Django) |
| **الجمع للمجموعات** | `/products/` لا `/product/` |
| **الشرطة في المسارات المركبة** | `/stock-movements/` لا `/stock_movements/` |
| **الأسفل في حقول JSON** | `created_at` لا `createdAt` |
| **المسار يعكس النطاق** | `/api/v1/catalog/products/` |

## نمط الموارد

```text
GET    /api/v1/catalog/products/              قائمة
POST   /api/v1/catalog/products/              إنشاء
GET    /api/v1/catalog/products/{slug}/       عنصر
PATCH  /api/v1/catalog/products/{slug}/       تعديل جزئي  ← المفضّل
PUT    /api/v1/catalog/products/{slug}/       استبدال كامل
DELETE /api/v1/catalog/products/{slug}/       حذف (soft)

POST   /api/v1/orders/{uuid}/cancel/          إجراء على مورد
```

**الإجراءات فعل في نهاية المسار، لا `?action=`.**

> **المعرّف:** `slug` للكتالوج · `UUID` لما عداه. **صفر معرّف تسلسلي** — [06-IDENTIFIERS.md](06-IDENTIFIERS.md).

# ٢. شكل الاستجابة

## قرار: بلا غلاف

```json
{ "id": "018f4e2a-...", "name_ar": "سماعة طبية", "price": "450.00" }
```

**لا** `{"data": {...}, "success": true}`.

| السبب | التفصيل |
|---|---|
| رمز HTTP يحمل النجاح | `success: true` مع `200` تكرار |
| اصطلاح DRF الافتراضي | لا مقاومة للإطار |
| أخف على الشبكة | |

**الاستثناء الوحيد:** القوائم المرقّمة (أدناه).

## أنواع القيم

| النوع | الصيغة | مثال |
|---|---|---|
| التاريخ والوقت | ISO 8601 بـ UTC | `2026-08-12T14:30:00Z` |
| التاريخ | ISO 8601 | `2026-08-12` |
| **المال** | **نص** لا رقم | `"450.00"` |
| النِّسب | نص | `"14.00"` |
| المعرّف | نص | `"018f4e2a-..."` |
| الفارغ | `null` لا `""` | |

> ⚠️ **المال نص إلزامًا.** `JSON.parse` في جافاسكربت يحوّل الأرقام إلى `double` ⟵ فقدان دقة. `450.00` تصير `450`، و`0.1 + 0.2` تصير `0.30000000000000004`. **النص يعبر بلا تشويه.**

## المبالغ المركّبة

```json
{
  "subtotal":     "450.00",
  "discount":     "50.00",
  "tax_rate":     "14.00",
  "tax_amount":   "56.00",
  "shipping":     "30.00",
  "total":        "486.00",
  "currency":     "EGP"
}
```

**كل استجابة مالية تحمل `currency`.** لا افتراض ضمني.

# ٣. الترقيم

## الافتراضي — بالمؤشر

```http
GET /api/v1/orders/?limit=20&cursor=cD0yMDI2LTA4LTEy
```

```json
{
  "results":  [ ... ],
  "next":     "https://api.example.com/api/v1/orders/?limit=20&cursor=cj0x",
  "previous": null
}
```

| القاعدة | القيمة |
|---|---|
| الافتراضي | 20 |
| الأقصى | 100 |
| **لا `count`** | كشف العدد الكلي تسريب معلومة تجارية |

## الاستثناء — بالإزاحة

لشاشات الأدمن التي تحتاج «صفحة ٥ من ٤٢»:

```json
{ "results": [...], "count": 842, "next": "...", "previous": "..." }
```

**مسموح فقط** حيث يملك المستخدم صلاحية رؤية العدد الكلي.

> **القوائم العامة والقوائم المملوكة للمستخدم ⟵ مؤشر بلا عدد.**

# ٤. الفلترة والترتيب والبحث

```http
GET /api/v1/catalog/products/
      ?category=slug
      &brand=slug
      &price_min=100&price_max=500
      &in_stock=true
      &created_after=2026-01-01
      &search=سماعة
      &ordering=-created_at
```

| النمط | المعنى |
|---|---|
| `field=value` | مساواة |
| `field_min` · `field_max` | مدى |
| `field_after` · `field_before` | مدى زمني |
| `field=a,b,c` | ضمن قائمة |
| `search=` | بحث نصي عبر حقول معرّفة |
| `ordering=field` · `-field` | تصاعدي · تنازلي |

**كل الفلترة من الخادم.** لا فلترة في العميل على بيانات مرقّمة.

> ⚠️ **الفلترة واعية بالسياسات.** المنتج المقيّد لا يظهر في النتائج ولا في العدد ولا في الفلاتر المتاحة — الفلترة في الـ **queryset** لا في الـ serializer.

# ٥. الأخطاء

## الشكل الموحّد

```json
{
  "code":    "INSUFFICIENT_STOCK",
  "message": "الكمية المطلوبة غير متوفرة",
  "detail":  "المتاح: 3 · المطلوب: 10",
  "fields":  null
}
```

| الحقل | الدور |
|---|---|
| `code` | **ثابت · إنجليزي · مقروء آليًا** — عليه يبني الفرونت منطقه |
| `message` | مترجم حسب `Accept-Language` — للعرض |
| `detail` | سياق إضافي · قد يكون `null` |
| `fields` | أخطاء التحقق لكل حقل · `null` لغيرها |

> **ممنوع أن يعتمد منطق الفرونت على `message`.** النص يتغير ويُترجم؛ `code` عقد ثابت.

## أخطاء التحقق

```json
{
  "code": "VALIDATION_ERROR",
  "message": "بيانات غير صالحة",
  "detail": null,
  "fields": {
    "email":    [{ "code": "UNIQUE",    "message": "هذا البريد مسجل بالفعل" }],
    "quantity": [{ "code": "MIN_VALUE", "message": "الكمية يجب أن تكون 1 على الأقل" }]
  }
}
```

## رموز HTTP

| الرمز | الاستخدام |
|---|---|
| `200` | نجاح |
| `201` | إنشاء |
| `204` | نجاح بلا محتوى |
| `400` | خطأ تحقق أو قاعدة عمل |
| `401` | غير مصادَق — أو التوكن منتهٍ |
| `403` | مصادَق ولا يملك الصلاحية **لهذا النوع من العمليات** |
| **`404`** | **غير موجود — أو موجود ولا يملكه** |
| `409` | تعارض حالة (انتقال غير مسموح) |
| `422` | مفهوم شكلًا ومرفوض دلاليًا |
| `429` | تجاوز حد المعدل |
| `500` | خطأ خادم |

### ⚠️ الفرق بين `403` و `404`

```text
GET /api/v1/orders/<uuid-طلب-شخص-آخر>/     ⟵ 404
GET /api/v1/orders/<uuid-غير-موجود>/       ⟵ 404
```

**ردّان متطابقان تمامًا.** لو أعاد الأول `403`، لصار الفرق بينهما أداة تعداد.

**`403` تُستخدم فقط** لغياب صلاحية على **نوع** العملية (مثلًا: موظف يحاول الوصول إلى `/api/v1/finance/`)، لا على مورد بعينه.

## كتالوج الأكواد

```text
المصادقة       AUTHENTICATION_REQUIRED · INVALID_CREDENTIALS · TOKEN_EXPIRED
               TOKEN_INVALID · ACCOUNT_SUSPENDED · ACCOUNT_BLOCKED
               EMAIL_NOT_VERIFIED

الصلاحيات      PERMISSION_DENIED · VERIFICATION_REQUIRED
               PRODUCT_ACCESS_DENIED

التحقق         VALIDATION_ERROR · REQUIRED · INVALID_FORMAT · UNIQUE
               MIN_VALUE · MAX_VALUE · MIN_LENGTH · MAX_LENGTH

المخزون        INSUFFICIENT_STOCK · PRODUCT_UNAVAILABLE · BATCH_EXPIRED

السلة والطلب   CART_EMPTY · PRICE_CHANGED · INVALID_STATE_TRANSITION
               ORDER_ALREADY_PAID · ORDER_CANNOT_BE_CANCELLED

الكوبونات      COUPON_NOT_FOUND · COUPON_EXPIRED · COUPON_LIMIT_REACHED
               COUPON_NOT_APPLICABLE · MINIMUM_ORDER_NOT_MET

الدفع          PAYMENT_FAILED · PAYMENT_GATEWAY_ERROR
               PAYMENT_METHOD_UNAVAILABLE

عام            NOT_FOUND · CONFLICT · RATE_LIMIT_EXCEEDED · INTERNAL_ERROR
```

**كل كود جديد يُضاف هنا وإلى `core/errors/`.**

# ٦. المصادقة

```http
Authorization: Bearer <access_token>
```

| القاعدة | القيمة |
|---|---|
| عمر الـ Access Token | **١٠ دقائق** |
| عمر الـ Refresh Token | ٧ أيام |
| التدوير | كل تجديد يصدر توكنين جديدين ويُبطل القديم |
| القائمة السوداء | مفعّلة |
| **فحص الإيقاف** | **مجموعة Redis تُفحص على كل طلب** — الإيقاف لحظي |

```text
POST /api/v1/auth/register/
POST /api/v1/auth/login/
POST /api/v1/auth/logout/
POST /api/v1/auth/token/refresh/
POST /api/v1/auth/verify-email/
POST /api/v1/auth/resend-verification/
POST /api/v1/auth/password/reset/            ← رد موحّد دائمًا
POST /api/v1/auth/password/reset/confirm/
POST /api/v1/auth/password/change/
GET  /api/v1/auth/me/
GET  /api/v1/auth/sessions/
POST /api/v1/auth/sessions/{uuid}/revoke/
```

> `password/reset/` يعيد **`200` دائمًا** سواء كان البريد مسجلًا أو لا. رد مختلف = أداة لكشف الحسابات.

# ٧. اللغة

```http
Accept-Language: ar
```

```text
ترويسة الطلب  →  تفضيل المستخدم  →  الافتراضي  →  العربية
```

| النوع | السلوك |
|---|---|
| **رسائل النظام** | مترجمة حسب اللغة المتفاوض عليها |
| **محتوى العملاء** | **كلا اللغتين دائمًا** — `name_ar` و`name_en` |

```json
{ "name_ar": "سماعة طبية", "name_en": "Stethoscope" }
```

> **السبب:** الفرونت قد يعرض اللغتين معًا (لوحة الأدمن مثلًا). إرسال المترجم فقط يمنع ذلك ويجبر على نداء ثانٍ.

**استثناء:** البريد يُرسَل بلغة **تفضيل المستلم**، لا لغة الطلب الذي أطلق الحدث.

# ٩. المنع التكراري (Idempotency)

للعمليات المالية:

```http
POST /api/v1/orders/
Idempotency-Key: 018f4e2a-9c3b-7d1e-a5f0-2b8c4d6e1a90
```

نفس المفتاح خلال ٢٤ ساعة ⟵ **نفس الاستجابة الأصلية** بلا تنفيذ ثانٍ.

**إلزامي على:** إنشاء الطلب · الدفع · الاسترداد · بيع POS.

**السبب:** نقرة مزدوجة أو إعادة محاولة على شبكة ضعيفة يجب ألا تنتج طلبين.

# ١٠. الحقول الحساسة

| القاعدة | التفصيل |
|---|---|
| **الأسرار لا تُقرأ أبدًا** | مفاتيح بوابات الدفع · التوكنات · الهاشات — **حقول للكتابة فقط حتى للأدمن** |
| **لا مفاتيح داخلية** | جداول `BigInt` لا تُصدّر `id` |
| **لا عدّادات لغير المصرّح** | `total_users` ليست بيانات عامة |
| **الملفات الحساسة** | رابط موقّع بصلاحية زمنية لا مسار مباشر |

```json
{
  "provider": "paymob",
  "is_active": true,
  "api_key": "••••••••1a2b"
}
```

# ١١. التوثيق

`drf-yasg` على `/api/v1/docs/`. كل نقطة نهاية توثّق: المصادقة · الصلاحيات · الطلب · الاستجابة · التحقق · **أكواد الأخطاء الممكنة** · الترقيم · الفلترة · الترتيب.

**نقطة نهاية بلا توثيق = غير منجزة.**

# ١٢. سياسة الإصدارات

| نوع التغيير | الأثر |
|---|---|
| **متوافق** — حقل جديد · قيمة جديدة في `enum` · نقطة نهاية جديدة | نفس `v1` |
| **كاسر** — حذف/إعادة تسمية حقل · تغيير نوع · تغيير دلالة | **`v2`** |

الفرونت **يتجاهل الحقول غير المعروفة** — إضافة حقل يجب ألا تكسر شيئًا.

`v1` تبقى مدعومة ٦ أشهر بعد صدور `v2`.

# ١٣. قائمة التحقق لكل نقطة نهاية

- [ ] المسار يعكس النطاق ويتبع الاصطلاح
- [ ] **لا معرّف تسلسلي** — `slug` أو `UUID`
- [ ] المصادقة والصلاحيات مصرّحة
- [ ] **فحص الملكية** — لا `queryset` مفتوح
- [ ] `404` موحّد لغير الموجود وغير المملوك
- [ ] المبالغ نصوص + `currency`
- [ ] الأخطاء بأكواد من الكتالوج
- [ ] الترقيم مطبّق · بمؤشر افتراضيًا
- [ ] الفلترة والترتيب من الخادم وواعيان بالسياسات
- [ ] `Idempotency-Key` على العمليات المالية
- [ ] تحديد المعدل مضبوط
- [ ] لا أسرار ولا مفاتيح داخلية في الاستجابة
- [ ] موثّقة في Swagger
- [ ] مغطاة باختبار: نجاح · فشل تحقق · بلا مصادقة · بلا صلاحية · **ملكية غير صحيحة**
