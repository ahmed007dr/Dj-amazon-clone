# `reporting/`

> يقرأ كل النطاقات، ولا يكتب في أيّ منها، ولا يستورده أحد

| | |
|---|---|
| **الطبقة** | تحت `devtools`، فوق كل شيء آخر |
| **يعتمد على** | كل النطاقات — بحكم التعريف |
| **يعتمد عليه** | لا شيء — ولا يجوز |
| **نماذج** | **لا شيء ولا هجرات** |

## جزآن

| | يجيب على |
|---|---|
| `services.py` + `api.py` | «كم بعنا؟» — مجاميع وملخّصات ورسوم |
| `export/` | «أعطني الصفوف لأسأل أنا» — تصدير سطري إلى إكسل |

الاثنان مختلفان تمامًا. التقرير يعطي رقمًا، والتصدير يعطي الصفوف التي وراءه.

# `export/` — التصدير

## لماذا هنا لا في تطبيق جديد؟

ميثاق `reporting` المكتوب في عقد الطبقات هو حرفيًا وصف التصدير: يقرأ كل
نطاق، ولا يكتب في أيّ منها، ولا يستورده أحد.

وهو **فوق `imports`** في الترتيب، فيستطيع قراءة `imports.spec` لتصدير
المنتجات بأعمدة قالب الاستيراد. والعكس ممنوع بالعقد — ولهذا تعيش المعرفة
المشتركة في `imports/spec.py` وتُقرأ من هنا.

وشرطه «بلا نماذج ولا هجرات» يبقى سليمًا: التصدير متزامن، بلا وظيفة مخزَّنة.

## ⚠️ التصدير مرآة الاستيراد

عائلتان:

**قوالب قابلة للعودة** — `products` و`variants` تخرج بأعمدة قالب الاستيراد
نفسها، والمراجع تخرج **رموزًا يقبلها المستورد** لا أسماء معروضة:
`medicines/painkillers` لا «مسكّنات»، و`pfizer` لا «فايزر».

```
تصدير المنتجات ──► تعديل الأسعار في إكسل ──► رفعه بنمط UPDATE_ONLY
```

هذا يغلق ثغرة تركها الاستيراد: تحديث أسعار أربعة آلاف صنف يحتاج ملفًا فيه
الرموز، ولم تكن هناك وسيلة للحصول عليه. ويحرسه اختبار يمرّ بالدورة كاملة.

**لقطات للتحليل** — الباقي. مسطّحة، بأسماء مقروءة، لا تعود للاستيراد.

## ⚠️ الأمن — أهم ما في الملف

| القاعدة | لماذا |
|---|---|
| **الأعمدة قائمة سماح لا استبعاد** | `values()` على الموديل كله يعني أن حقلًا يُضاف بعد ستة أشهر يبدأ بالتسرّب بلا أن يقرّره أحد |
| **صلاحية لكل مجموعة** | مخزن الفرع يصدّر المخزون ولا يصدّر العملاء؛ ومن يرى الأرباح لا يصدّر قائمة الحسابات بحكم ذلك |
| **الفلترة عند العرض لا عند التنزيل فقط** | زر يعطي 403 دائمًا يُقرأ كعطل لا كحدّ؛ وقائمة المجموعات نفسها معلومة |
| **بيانات الاتصال بوابة ثانية** | تصدير العملاء بلا اتصال تحليل؛ ومعه قائمة بريدية تخرج من الشركة بنقرة |
| **الطلب بلا صلاحية يُرفض لا يُقصّ** | عمود يُحذف بصمت يعطي ملفًا يظنّه الأدمن كاملًا |
| **كل تنزيل يكتب `AuditAction.EXPORT`** | «مَن أنزل قائمة كل العملاء قبل أن يستقيل؟» سؤال لا إجابة له في أي مكان آخر |
| **سقف ٥٠٬٠٠٠ صف يُفحص قبل القراءة** | Passenger يقتل الطلب الطويل؛ والاكتشاف بعد ثلاثين ثانية يعطي اتصالًا ميتًا بلا رسالة |
| **نطاق `throttle` أضيق من كل شيء** | ٢٠/دقيقة — سخيّ لإنسان وعديم الفائدة لسكربت |

**لا يخرج أبدًا:** هاش كلمة المرور · التوكنات · `ProviderCredential.value` ·
أي حقل مشفّر · مفاتيح `BigInt` الداخلية · مسار وثيقة أو مرفق مصروف ·
استجابة بوابة الدفع الخام · مفاتيح منع التكرار.

ويحرس هذا اختبار يمرّ على **كل مجموعة مسجّلة** بما فيها ما يُضاف لاحقًا —
لأن الاختبار لكل مجموعة على حدة يحرس ما تذكّر أحدهم أن يكتب له اختبارًا.

## ⚠️ الأرقام أرقام والتواريخ تواريخ

ADR-31 يفرض المال **نصًّا في JSON** لأن `JSON.parse` يفقد الدقة. في xlsx
العكس هو الصحيح للسبب نفسه — الأمانة تجاه القارئ: عمود نصّي لا يُجمَع بـ
`SUM` ولا يُرتَّب، ويعرض مثلث «رقم مخزَّن كنص» في كل خلية. وغرض الملف كله
التحليل.

و**لا معادلات**. المعادلة المصدَّرة تُعاد حوسبتها يوم يُفتح الملف، فتقرير
محفوظ في مارس يغيّر أرقامه بنفسه؛ وأسوأ: معادلة تشير إلى عمود رتّبه القارئ
تنتج رقمًا خاطئًا معقولًا. كل عمود محسوب — إجمالي السطر، الهامش، الأيام
المتبقية — يُحسب هنا ويخرج رقمًا.

## ⚠️ ورقة `_عن هذا الملف`

أنفع ورقة في المصنَّف وأقلّها طلبًا. الملف يُرسَل بالبريد ويُحفَظ على سطح
مكتب ويُفتَح بعد ثلاثة أسابيع؛ بلا هوية لا أحد يعرف أي فترة يغطّي ولا أي
فلاتر أنتجته — فيُقارَن بربع سنة آخر ويُبنى قرار على الفرق بين رقمين لا
علاقة بينهما.

تحمل: المجموعة · الفلاتر المطبَّقة · **هل شمل بيانات الاتصال** · وقت
التوليد · مَن ولّده · عدد الصفوف.

## البنية

```
export/
  registry.py         ← سجل المجموعات: الأعمدة · الصلاحية · الفلاتر
  writer.py           ← كتابة xlsx (write_only) + التنسيق + _meta
  api.py              ← نقطتان
  datasets/
    _common.py        ← الفلاتر المشتركة والتدفّق
    inventory.py · catalog.py · customers.py · sales.py · purchasing.py · finance.py
```

## نقطتان لا أكثر

```
GET /api/v1/reports/exports/          ← ما يحقّ لهذا المستخدم تصديره + فلاتر كل مجموعة + قوائم الاختيار
GET /api/v1/reports/exports/{key}/    ← الملف، بالفلاتر كـ query params
```

## إضافة مجموعة جديدة

في الوحدة المناسبة تحت `datasets/`:

```python
register(Dataset(
    key="...", label="...", group=Group.X, permission=CanManageY,
    filters=[Filter(...)],
    columns=lambda contact: [Column("العنوان", Kind.MONEY), ...],
    rows=lambda filters, contact: ...,      # يعيد tuples بترتيب الأعمدة
    count=lambda filters: ....count(),
))
```

ثم أضف الوحدة إلى `datasets/load_all()` إن كانت جديدة. **الاستيراد هو
التسجيل** — وحدة غائبة عن تلك القائمة لا تصدّر شيئًا وتبدو سليمة على القرص.

⚠️ وعدد القيم في كل `tuple` يجب أن يطابق عدد الأعمدة بالضبط، في الحالتين
مع بيانات الاتصال وبدونها. يحرسه اختبار يمرّ على كل مجموعة.

## الواجهة — مكانان

| | |
|---|---|
| `/admin/exports` | كتالوج للاكتشاف: «ما الذي أستطيع إخراجه أصلًا؟» |
| `<ExportButton>` | في شاشة البيانات نفسها، **يحمل فلاترها المعروضة** |

الثاني هو ما يُستخدم فعلًا. والأول بلا `RequirePermission` عمدًا: كل مجموعة
تفحص صلاحيتها، والشاشة تعرض ما يحقّ للحساب — وربطها بصلاحية واحدة إمّا
يحجب مخزن الفرع عن مخزونه أو يفتحها لمن لا يملك شيئًا.

## الحدود

| | |
|---|---|
| صفوف الملف الواحد | ٥٠٬٠٠٠ (نفس رقم `imports.spec.MAX_ROWS_PER_FILE`) |
| فترة إلزامية | `stock-movements` · `order-lines` |
| المعدل | ٢٠ تنزيلًا/دقيقة |

الرقم متطابق مع الاستيراد عمدًا: التصدير والاستيراد لنفس المجموعة يجب أن
يتفقا على ما يسع ملفًا واحدًا، وإلا انكسرت الدورة عند الحجم الذي يهمّ.
