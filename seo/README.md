# `seo/`

> أرشفة محركات البحث — `robots.txt` و `sitemap.xml`

| | |
|---|---|
| **الطبقة** | فوق نطاقات العمل، بجوار `ops` |
| **يعتمد على** | `catalog` · `academic` · `access` |
| **يعتمد عليه** | لا شيء — ولا يجوز |
| **مثبّت في الإنتاج** | ✅ نعم |

## لماذا تطبيق منفصل؟

الخريطة تجمع منتجات `catalog` وحزم `academic` وترشّحها بسياسات
`access`. لا نطاق من الثلاثة يجوز أن يستورد الآخر — والخريطة ليست
منطق أيٍّ منها أصلًا: هي عرض تشغيلي للكتالوج العام.

## ⚠️ الروابط تشير إلى الواجهة لا إلى الـ API

`FRONTEND_BASE_URL` هو الموقع الذي يزوره الإنسان. خريطة بمضيف
الـ API تقود جوجل إلى JSON لا إلى صفحات.

## ⚠️ النشر: المسارات تُوجَّه من أصل الواجهة

المزحف يطلب `/robots.txt` و`/sitemap.xml` من **جذر الموقع الذي
يزوره** — أي أصل الواجهة. والملفان يُولَّدان في الخادم.

`nginx` أمام الواجهة:

```nginx
location = /robots.txt  { proxy_pass https://api.example.com/robots.txt; }
location = /sitemap.xml { proxy_pass https://api.example.com/sitemap.xml; }
```

بدون هذا التوجيه يبقى الملفان صحيحين لكن لا يقرأهما أحد.

## ⚠️ `SEO_INDEXING_ENABLED`

الافتراضي **`False`**. بيئة تجريبية مفهرسة تنافس الموقع الحقيقي
على نفس الكلمات وتعرض بيانات اختبار كأنها منتجات — والافتراضي
المغلق يجعل نسيان الضبط خطأً آمنًا لا كارثة تسويقية.

يُفعَّل في الإنتاج وحده:

```bash
SEO_INDEXING_ENABLED=True
```

## ⚠️ ما لا يعالجه هذا التطبيق

الخريطة تدلّ المزحف على الصفحات؛ ولا تجعل محتواها موجودًا في
HTML. الواجهة SPA (ADR-37): جوجل ينفّذ JavaScript فيرى المحتوى
بتأخّر، أما فيسبوك وواتساب فلا ينفّذانه — **معاينة الروابط تبقى
ناقصة حتى يُنفَّذ التوليد المسبق** الموصوف في ADR-37.

وسوم `<meta>` و JSON-LD تُحقن وقت التشغيل من
`web/src/shared/seo/` — تكفي جوجل ولا تكفي معاينة واتساب.
