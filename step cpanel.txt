١. اقلب السويتش عندك          config/environment.py
٢. ابنِ الواجهة               cd web && npm run build
٣. ارفع الكود                 → /home/medboxne/med-box
٤. ارفع web/dist              → /home/medboxne/public_html
٥. اعمل .env.production        على السيرفر
٦. ثبّت الاعتمادات             pip install -r requirements/base.txt
٧. migrate · collectstatic · pybabel
٨. touch tmp/restart.txt
٩. ارجّع السويتش False         عندك عشان تكمل شغل
١٠. أعد تشغيل خادم الواجهة     cd web && npm run dev


⚠️  الخطوة ٦ — بدونها أي اعتماد جديد لا يصل السيرفر أبدًا.

    الاعتمادات معلَنة في requirements/base.txt، وكانت هذه القائمة تقفز
    من رفع الكود إلى migrate مباشرةً. فظهر ModuleNotFoundError: openpyxl
    — وهو لا يكسر شاشة الاستيراد وحدها: السلسلة
    config/urls.py ← imports/api.py ← openpyxl على مسار الـ URLconf الجذري،
    فغياب مكتبة جداول بيانات يُسقط المتجر والسلة والدفع معًا،
    برسالة تشير إلى openpyxl في مكان لا علاقة له بما يستخدمه العميل.


⚠️  الخطوة ١٠ — الواجهة لا تلتقط قلب السويتش وهي شغّالة.

    web/vite.config.ts يقرأ IS_PRODUCTION من config/environment.py
    ويخبز VITE_API_BASE_URL **عند الإقلاع مرة واحدة**. فإرجاع السويتش
    في الخطوة ٩ لا يغيّر خادمًا يعمل: يظل يخدم https://med-box.net/api/v1
    بينما أنت على localhost:5173.

    والعَرَض يضلّل تمامًا — «تحقّق من اتصالك بالإنترنت» —
    فتفحص الشبكة وخادم Django وكلاهما سليم.


البريد الوارد — مرة واحدة على السيرفر (وإلا لا يظهر ردّ العميل في /admin/mail)

    أ. cPanel ← Email Accounts       أنشئ support@med-box.net
    ب. /admin/mail ← الحسابات        حساب جديد: الاتجاه «وارد»
                                      IMAP mail.med-box.net · 993 · SSL/TLS
                                      المستخدم support@med-box.net (العنوان كاملًا) · المجلد INBOX
    ج. حساب noreply في نفس الشاشة    «الردّ إلى» = support@med-box.net
    د. cron كل ٥ دقائق               python manage.py run_periodic --job mail
                                      (يشمل التسليم + سحب الوارد — راجع docs/shared/06-DEPLOYMENT.md §٩)

    تحقّق:
      ١) زر «اختبار IMAP» في بطاقة الحساب        ⇐ اتصال ناجح + عدد الرسائل
      ٢) python manage.py run_periodic --job fetch_inbound_mail
      ٣) أرسل من Gmail إلى support@med-box.net      ⇐ تظهر في «الوارد» خلال ٥ دقائق
      ٤) اضغط Reply على رسالة نظام (استعادة كلمة مرور) ⇐ المستلم support@ لا noreply@


⚠️  البريد الوارد — بدونه ردّ العميل «لم يصل» وهو وصل فعلًا.

    رسائل النظام تخرج من noreply@med-box.net. بلا «الردّ إلى» يذهب ردّ العميل
    إلى ذلك العنوان، ولا حساب يسحب منه أحد — فلا يظهر في أي مكان.
    وأول سحب يأخذ أحدث ٥٠ رسالة فقط (الأرشيف القديم لا يُستورد عمدًا).
